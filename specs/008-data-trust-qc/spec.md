## User Scenarios & Testing *(mandatory)*

### User Story 1 - Quote a number without double-checking it (Priority: P1)

A seller reading a figure off the atlas to a client says it out loud without first going to
verify it somewhere else.

**Why this priority**: The product's entire value is that its numbers can be spoken in a meeting.
A number that needs checking first is worse than no number, because it costs time *and* trust.

**Independent Test**: Open the data sources panel and confirm it states what was verified and
when, generated by an actual check rather than written by hand.

**Acceptance Scenarios**:

1. **Given** the data sources panel, **When** the user opens it, **Then** it leads with a
   verification line naming the layer count, place count and the date the check ran.
2. **Given** that line, **When** it renders, **Then** its content comes from the checker's own
   output, never from hand-maintained text.
3. **Given** a data edit that introduces a gap, **When** the checker runs, **Then** it fails
   rather than allowing the edit to ship.

---

### User Story 2 - Catch an incomplete layer before a client does (Priority: P1)

A layer that should hold a known number of places cannot ship holding fewer.

**Why this priority**: The seeded defect — 8 polyclinics when Singapore has 26 — is exactly the
kind of gap a client spots instantly, and it passed every check that existed at the time.

**Independent Test**: Truncate an enumerable layer and confirm the checker fails.

**Acceptance Scenarios**:

1. **Given** a layer with a known real-world size, **When** the checker runs, **Then** it enforces
   a completeness floor for that layer.
2. **Given** a layer truncated below its floor, **When** the checker runs, **Then** it fails
   loudly.
3. **Given** a new enumerable layer, **When** it is added, **Then** its floor is added alongside
   it.

---

### User Story 3 - Catch an entry that contradicts itself (Priority: P1)

A place whose point and whose drawn footprint describe two different locations fails the check
instead of rendering confidently in the wrong place.

**Why this priority**: Both user-reported defects were this class — an entry stitched from two
campuses, and a footprint left behind after a campus moved. Bounds, names and duplicate checks
all passed them, because each field was individually valid.

**Independent Test**: Attach a footprint from a different site to a place and confirm the checker
fails.

**Acceptance Scenarios**:

1. **Given** a place with both a point and a footprint, **When** the checker runs, **Then** it
   verifies the point lies inside or close to the footprint.
2. **Given** a genuinely large campus, **When** the checker runs, **Then** it passes rather than
   false-alarming.
3. **Given** an institution with several campuses, **When** it is represented, **Then** each
   campus is its own place with its own extent.
4. **Given** a campus with no footprint available, **When** it renders, **Then** it shows an
   honest approximate extent rather than an invented polygon.

---

### User Story 4 - Unwind a stacked map in one tap (Priority: P2)

After stacking place layers, shading, heat and rail focus, the user clears the map layers without
undoing each control by hand — and without losing their route selection.

**Why this priority**: Housekeeping, not correctness — but it is the difference between exploring
freely and being cautious about turning things on.

**Acceptance Scenarios**:

1. **Given** a heavily stacked map, **When** the user taps reset in the layers panel, **Then** all
   place layers, picks, labels, shading, heat and rail focus clear.
2. **Given** that reset, **When** it completes, **Then** the route selection is untouched.

### Edge Cases

- A large campus whose point legitimately sits near the edge of its footprint — must pass.
- A chain with many identically named outlets — must not trip the duplicate check.
- Two places sharing a building and therefore coordinates — must not trip the duplicate check.
- A layer whose real-world size genuinely changes — the floor must be updated deliberately, as a
  reviewed edit, not silently lowered to make a failing check pass.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: A checker MUST run over every place-data file and MUST be runnable offline.
- **FR-002**: The checker MUST verify names are present, coordinates fall within Singapore, and
  no exact-duplicate rows exist.
- **FR-003**: The checker MUST verify point↔footprint consistency and fail when an entry
  contradicts itself.
- **FR-004**: The checker MUST enforce completeness floors for layers of known real-world size.
- **FR-005**: Each checker run MUST write a machine-generated report recording layers, place
  count, checks passed and the verification date.
- **FR-006**: The application's data sources panel MUST lead with that generated verification
  line and MUST NOT carry a hand-written trust claim.
- **FR-007**: The checker MUST be run after any place-data edit, and every failure fixed before
  committing.
- **FR-008**: A multi-campus institution MUST be represented as one place per campus.
- **FR-009**: A place without a footprint MUST be able to declare an approximate extent.
- **FR-010**: The layers panel MUST provide a reset that clears all layer state and leaves the
  route selection untouched.

### Key Entities

- **Completeness floor**: The minimum number of places a named layer must contain for its
  real-world set to be considered fully represented.
- **Verification report**: The checker's generated output — layer count, place count, checks
  passed, date — and the sole source of the app's trust line.
- **Approximate extent**: A declared radius standing in for a footprint that is not available.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Truncating an enumerable layer fails the checker (verified by sabotage test).
- **SC-002**: An entry stitched from two sites fails the checker.
- **SC-003**: The app's verification line is never written by hand and always reflects the last
  actual check.
- **SC-004**: A seller can quote any figure in the app without independently verifying it first.
- **SC-005**: One tap returns a heavily stacked map to a clean state without losing the selection.

## Assumptions

- The checker runs locally on demand; there is no CI in this repository to run it automatically,
  so the discipline is enforced by the constitution and by review.
- Completeness floors are maintained by hand as real-world sets change, and changing one is a
  reviewed edit.
- 150 m is the working tolerance for point-inside-or-near-footprint; large campuses pass.
- The route selection and the layer stack are separate concerns with separate resets.
